## Startup validation

`Config.Validate()` applies in every environment, `TC_ENV=development` included. It refuses to start with:

- the built-in JWT secret, or one shorter than 32 bytes;
- the default `minioadmin` credentials;
- an empty or wildcard CORS list;
- a `TC_WORKSPACE_TIMEZONE` the tz database does not know.

One guard has an allowance variable: `TC_ALLOW_DEFAULT_OBJECT_STORAGE_CREDENTIALS` for the storage credentials. The others have none. `TC_ENV=development` adds `/auth/dev-login` and nothing else.

## Local stack variables

`compose.yml` reads `TC_DB_PORT` (default 33306), `TC_DB_ROOT_PASSWORD`, `TC_DB_NAME`, `TC_DB_USER`, `TC_DB_PASSWORD`, `TC_S3_PORT` (default 9000, bound to loopback), `TC_MAILPIT_SMTP_PORT` (default 1025) and `TC_MAILPIT_UI_PORT` (default 8025). Both mailpit ports are bound to loopback.

## Self-hosting stack variables

`compose.prod.yml` also reads `TC_PUBLIC_HOST` (the hostname the certificate is issued for; required), `TC_TLS_DIR` (host directory holding the certificates, mounted as `/etc/letsencrypt`; default `/etc/letsencrypt`) and `TC_ACME_WEBROOT` (host directory `certbot --webroot` writes challenges to; default `./acme`). See [Deployment](deployment.md#tls-certificate).

## Test variables

The E2E suite reads `TC_TEST_INTEGRATION` (any value enables it) and `TC_TEST_STORAGE` (any value also runs the tests that need object storage; without it they skip). The tests that check the answer for absent object storage skip when `TC_TEST_STORAGE` is set, so a complete check is two runs; see [Development](development.md#testing).
